# AI Video Meeting Analyzer — DZ Light / DZ Pro

Локальное приложение для транскрибации русских и английских видеовстреч и создания структурированного конспекта. Исходное видео и распознавание обрабатываются локально; видео удаляется после обработки. Для конспекта расшифровка передаётся выбранному внешнему AI-провайдеру и затем хранится в локальной SQLite базе.

## Требования

- Python 3.11+
- Интернет при первом запуске, чтобы установить зависимости и загрузить мультиязычную Faster-Whisper модель
- API ключ выбранного summarizer (по умолчанию DeepSeek); вызовы могут тарифицироваться

## Установка и запуск (Windows PowerShell)

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./setup.ps1
# Добавьте DEEPSEEK_API_KEY в локальный .env
./start.ps1
```

Откройте `http://127.0.0.1:8000`. Выберите MP4/WebM: обработка начнётся автоматически. Первый запуск может занять дольше из-за скачивания модели (кэш хранится в `.cache/huggingface` на диске проекта). `data/meetings.sqlite3` хранит историю, `.env` и все данные остаются локальными.

## Настройки

В `.env` задаются `AI_PROVIDER=deepseek|openai|gemini`, ключ и модель соответствующего API, `WHISPER_MODEL`, `WHISPER_DEVICE`, `WHISPER_COMPUTE_TYPE`, `MAX_UPLOAD_MB`, `HOST`, `PORT`. Смена провайдера не требует изменений бизнес-логики.

## Импорт из Google Drive (DZ Pro)

Вставьте публичную ссылку на отдельный файл вида `https://drive.google.com/file/d/FILE_ID/view`. В Google Drive установите общий доступ «Все, у кого есть ссылка» (роль «Читатель») и убедитесь, что Drive разрешает скачивание. Приложение не входит в аккаунт пользователя и не использует OAuth. Backend преобразует share URL в прямой download request, проверяет домен/сеть, размер, время и сигнатуру MP4/WebM, затем передаёт временный файл тому же pipeline, что и ручная загрузка. Страницы входа и подтверждения отклоняются с понятной ошибкой. Источник, этап и нормализованная ссылка сохраняются; повторная ссылка открывает существующую встречу без повторного AI-запроса.

Если файл недоступен анонимно по публичной ссылке, приложение объяснит проблему. Скачайте его вручную и используйте обычную загрузку. Максимальный размер одинаков для ручного и облачного импорта (`MAX_UPLOAD_MB`).

## Развёртывание DZ Pro

Локальный запуск остаётся полноценным режимом работы. Для разделённого размещения предусмотрен один frontend build: `node scripts/build_frontend.mjs` создаёт статический пакет в `frontend-dist`. На Vercel задайте несекретную переменную `PUBLIC_API_BASE_URL` с HTTPS-адресом Python backend. Backend запускается из `Dockerfile`; в hosting-панели ему нужны постоянный том `/data`, `DEEPSEEK_API_KEY` (или ключ выбранного провайдера), `DATA_DIR=/data`, `HF_HOME=/data/model-cache`, `HOST=0.0.0.0` и точный `CORS_ALLOWED_ORIGINS` с origin фронтенда.

Минимальная архитектура для одиночной учебной демонстрации — статический frontend на Vercel и один постоянно работающий Docker backend на VPS с постоянным диском. Это сохраняет одну кодовую базу, локальную SQLite и модель Whisper на томе, не требует отдельной managed database, object storage или очереди. Один backend экземпляр обязателен: SQLite и in-process worker не предназначены для горизонтального масштабирования. Перед публичным запуском нужны подтверждённые TLS/домен, аутентификация или защита preview, ограничения запросов/расходов и резервное копирование `/data`; сейчас публичный backend не защищён от произвольного инициирования AI-обработки.

Конфигурации не публикуют сервисы и не создают hosting resources. Пошаговые требования и известные ограничения описаны в `DEPLOYMENT_READINESS.md`.

Будущие режимы демонстрации зафиксированы в `DEMO_MODES.md`: краткосрочный защищённый Teacher Live Demo и Public Showcase только с заранее подготовленными результатами. Оба режима пока не развернуты. Редакторская проверенная EN-версия примера находится в `DEMO_SUMMARY_EN_REVIEWED.md`; это отдельный материал, оригинальные AI-результаты в истории приложения не менялись.
