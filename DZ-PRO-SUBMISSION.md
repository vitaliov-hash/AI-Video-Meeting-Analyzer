## Дополнение Stage 4 — статический Showcase

Ветка Stage 4 добавляет статический режим показа с синтетическими RU/EN материалами. Он не обращается к FastAPI, `/api/meetings`, Faster-Whisper или DeepSeek. Исходная версия примера и редакторская версия подписаны отдельно; обе транскрипции и конспекты вымышлены. Защитные механизмы Teacher Preview реализованы локально в текущей feature branch, но режим не включён и не развёрнут.

Инструкция для передачи преподавателю: `TEACHER_HANDOUT.md`. Права на реальные учебные видео и их транскрипты не подтверждены, поэтому они не включены в Showcase, скриншоты и публичный пакет.

## Облачный источник

Для импорта выбран Google Drive. Требуется публичный URL отдельного файла MP4/WebM; приложение принимает стандартные share-ссылки `/file/d/FILE_ID/view`, без OAuth или доступа к Gmail.

Backend валидирует host, HTTPS, порт, DNS IP, редиректы, длительность и максимальный размер скачивания. По сигнатуре определяет MP4/WebM; HTML страницы входа/подтверждения не обходит. Источник, canonical share URL и текущий этап сохраняются в SQLite; дубли URL не запускают повторный pipeline. Ручная загрузка и Drive import используют один `process_video()`.

Живой E2E выполнил анонимное получение WebM 11,484,674 bytes, извлечение аудио, реальную транскрибацию Faster-Whisper `small` (4:02, язык `en`, p=.99, 3,325 символов) и ровно один реальный DeepSeek анализ (HTTP 200; usage 1,106 prompt + 282 completion = 1,388 tokens). Результат сохранён; перезагрузка страницы, список, открытие карточки и повтор ссылки подтвердили persistence/dedup без повторного AI вызова. Общее время — 632.19 s. Ссылка, Drive ID и содержание записи в пакет не включены.

Автоматическая проверка числовых утверждений нашла их в транскрипте, но строгая проверка пересечения значимых слов не прошла. Смысловая корректность требует ручной сверки по исходной записи; это ограничение не скрывается.

## Демонстрация

Достаточно одной записи длительностью 2–5 минут. Видео перед публикацией ссылки должно быть собственным или иметь согласие/разрешение на обработку и показ. В Google Drive задайте «Все, у кого есть ссылка» → «Читатель», скопируйте share URL. Вставьте в приложение, покажите стадии и результат, обновите страницу, затем вставьте ту же ссылку повторно и убедитесь, что открылась прежняя встреча.

Не загружайте несколько записей без необходимости. Для живой демонстрации используйте один короткий файл, на который есть разрешение на обработку и показ; реальные клипы с неподтверждёнными правами не публикуются.

## Финализация DZ Pro — подготовка выдачи

- Публичное раскрытие исходного репозитория: **NOT SAFE**. В достижимой Git-истории есть личные Git author identities (в отчёте не перечисляются). Временный переход Private → Public откроет всю историю; последующий возврат в Private не отзывает сделанные копии. Сохраняйте исходный репозиторий Private. Если преподавателю нужен публичный просмотр, потребуется отдельный очищенный submission-репозиторий с отфильтрованной историей и только проверенными материалами.
- Локально обнаружены недостижимые Git-объекты, содержащие приватный Drive identifier; по проверке их SHA отсутствуют на GitHub и они не достижимы из опубликованных refs. Не запускайте `git gc`/prune до отдельного решения о сохранении локальных объектов.
- Доступные GitHub Actions логи проверены без выгрузки персональных значений; секретов/личных ссылок не обнаружено. У проверенных прошлых runs нет artifacts. В repository отслеживаются только synthetic Showcase data и синтетические скриншоты; реальные видео, результаты SQLite, ключи и модели не включены. Источники реального тестового видео имеют неподтверждённые права.
- Учитель получает доступ к приватному исходнику через добавление его собственного GitHub аккаунта как collaborator; имя аккаунта преподавателя пока не предоставлено.
- Vercel Showcase остаётся статическим режимом без backend и платных AI вызовов. Нет SLA; выключенный по умолчанию backend требует ручной активации после отдельного подтверждения и проверки прав на запись.
