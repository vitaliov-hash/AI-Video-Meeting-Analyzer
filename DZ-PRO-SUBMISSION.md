# DZ Pro — пакет сдачи и статус проверки

**Статус: локальная реализация и реальный Cloud E2E завершены; публикация не выполнялась.** GitHub remote и работающий Vercel deployment не настроены и не входят в этот локальный контрольный этап.

## Облачный источник

Для импорта выбран Google Drive. Требуется публичный URL отдельного файла MP4/WebM; приложение принимает стандартные share-ссылки `/file/d/FILE_ID/view`, без OAuth или доступа к Gmail.

Backend валидирует host, HTTPS, порт, DNS IP, редиректы, длительность и максимальный размер скачивания. По сигнатуре определяет MP4/WebM; HTML страницы входа/подтверждения не обходит. Источник, canonical share URL и текущий этап сохраняются в SQLite; дубли URL не запускают повторный pipeline. Ручная загрузка и Drive import используют один `process_video()`.

## Проверка публичного импорта

Живой E2E выполнил анонимное получение WebM 11,484,674 bytes, извлечение аудио, реальную транскрибацию Faster-Whisper `small` (4:02, язык `en`, p=.99, 3,325 символов) и ровно один реальный DeepSeek анализ (HTTP 200; usage 1,106 prompt + 282 completion = 1,388 tokens). Результат сохранён; перезагрузка страницы, список, открытие карточки и повтор ссылки подтвердили persistence/dedup без повторного AI вызова. Общее время — 632.19 s. Ссылка, Drive ID и содержание записи в пакет не включены.

Автоматическая проверка числовых утверждений нашла их в транскрипте, но строгая проверка пересечения значимых слов не прошла. Смысловая корректность требует ручной сверки по исходной записи; это ограничение не скрывается.

## Автоматические проверки

Тесты без сети/AI API покрывают нормализацию Drive URL, отклонение посторонних доменов, видео фикстуру, HTML вместо файла, лимит скачивания, отказ внешнего redirect, сохранение source, миграцию старой Lite базы, dedup и приватность журналов. Последний isolated Quality Gate: **28 passed**; Ruff, compileall, JS syntax, Vercel frontend build, secrets scan и `git diff --check` прошли. Runtime HTTP/CORS smoke проходил ранее. Реальный live E2E описан выше; новых платных AI-запросов не выполнялось.

## Ручная проверка AI-конспекта

По сохранённой EN транскрипции сверены все summary sections. Содержание в целом опирается на запись, однако:

- фамилия распознана как “Stepano”; официальный протокол слушаний указывает **Daniel P. Stipano**;
- сказано 14 запросов, но разбивка 1 + 3 + 9 даёт 13; исходная речь противоречива, а конспект не отметил это;
- единственный `decisions` элемент описывает отсутствие решения и должен считаться unresolved вопросом;
- последний open question о закрытии девяти запросов разумно следует из контекста, но напрямую не задавался;
- явных назначенных задач, владельцев или сроков в записи нет.

Сохранённая встреча не редактировалась, AI повторно не запускался. Prompt для будущих анализов уточнён, добавлен регрессионный test. Реальный AI-анализ после этой правки не выполнялся. Источник проверки написания имени и чисел — [официальный протокол слушаний GovInfo](https://www.govinfo.gov/content/pkg/CHRG-113shrg81437/pdf/CHRG-113shrg81437.pdf).

## Демонстрация

Достаточно одной записи длительностью 2–5 минут. Видео перед публикацией ссылки должно быть собственным или иметь согласие/разрешение на обработку и показ. В Google Drive задайте «Все, у кого есть ссылка» → «Читатель», скопируйте share URL. Вставьте в приложение, покажите стадии и результат, обновите страницу, затем вставьте ту же ссылку повторно и убедитесь, что открылась прежняя встреча.

Не требуется загружать все записи. Nival клип на 6:26 длиннее рекомендуемого диапазона 2–5 минут; выбирайте только одну запись из подходящих коротких файлов и только при наличии права на её публикацию по общей ссылке.

## GitHub и Vercel

Remote отсутствует; push и публикации не выполнялись. Подготовлена архитектура статического frontend на Vercel и отдельного Python Docker backend с постоянным `/data`, в одной кодовой базе. Это single-instance demo architecture: SQLite и in-process worker не масштабируются, а API пока не имеет аутентификации/rate limit. Требуются платный backend host, секреты в его панели, подтверждение GitHub/Vercel ресурсов, аутентификация и отдельное согласование публикации. Подробности в `DEPLOYMENT_READINESS.md`.
